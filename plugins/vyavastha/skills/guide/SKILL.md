description: "How to use the Vyavastha plugin: signing in, turning it on in a project, its commands, and what it sends and shares. Use when the developer asks how to use, connect, sign in to or set up Vyavastha, how to turn it on or off, what it does, or what it shares with their team."
---

Vyavastha connects Claude Code to the developer’s team. In a project where it is on, it checks each request against what the team has said and decided before you change code, sums each session up for teammates under categories the developer controls, answers questions about the team, and lets the developer ask teammates’ agents. It is off in every project until the developer turns it on there, and from a project that is off it sends nothing of the developer’s work.

The plugin answers its own commands itself, before they reach you, so you cannot run them for the developer. Tell the developer which phrase to send, as a message of its own. In Claude Code most of them are also slash commands, such as /vyavastha:sign-in, /vyavastha:on and /vyavastha:help, which the developer can run instead.

To start: “vyavastha sign in” opens the sign-in page in the browser with a code to enter there, and once they approve, the next message finishes connecting, in any project. Then “vyavastha on” in each project the developer wants it in (“vyavastha off” stops it there). After that they just work: every message gets one line saying what was sent to Vyavastha and what came of it. “vyavastha help” shows everything, “vyavastha status” says whether they are signed in and whether it is on, and “vyavastha check” tests the setup and says how to fix each problem.

What it shares, and how to change it: “vyavastha settings” lists every setting. Summaries (“vyavastha summaries on” and “vyavastha summaries off”) keep the developer’s messages and your replies in a chat of their own in Vyavastha and sum them up for teammates, under categories the developer chooses to show there. Code sharing (“vyavastha share code on” and “vyavastha share code off”, off until they turn it on) also sends their uncommitted changes for the check; teammates see only a short summary, never the code, and key files, ignored files, machine-written files and files that aren’t text are never sent. Otherwise, from a project that is on, each message’s words, the repository and branch, and changed files’ names are sent. “vyavastha shared” lists everything this session sent.

Teammates: “vyavastha inbox” shows what teammates asked of the developer, and “vyavastha ask <name>: <question>” asks a teammate’s agent, which answers only from what both of them can already see.
